# 커피 달력

동료들이 돌아가며 커피를 살 때 "언제 누가 몇 잔을 샀는지"를 달력에 기록해 같이 보는 웹앱입니다.
다음 순번을 추천하지 않습니다. 기록과 합계만 보여 줍니다.

- 화면: 빌드 없는 정적 파일(GitHub Pages)
- 저장소: 구글 시트 + Apps Script 웹 앱

## 공개 범위

**URL을 아는 사람은 누구나 이름과 기록을 볼 수 있고, 비밀번호는 쓰기만 막습니다.**

- 웹 앱을 "모든 사용자" 액세스로 배포하므로 읽기에는 로그인도 비밀번호도 필요 없습니다.
- 저장소를 공개하면 `config.js`에 넣은 웹 앱 URL도 공개됩니다. 공개되어도 괜찮은 이름만 기록해 주세요.
- 비밀번호는 입력한 기기의 브라우저(localStorage)에 저장됩니다. 공용 PC에서는 화면 아래의 "이 기기에서 비밀번호 지우기"를 눌러 주세요.

## 배포 절차

1. **시트 생성**: 구글 시트를 새로 만듭니다. 이름은 자유입니다.
2. **Apps Script 열기**: 시트 메뉴에서 확장 프로그램 → Apps Script를 엽니다.
3. **코드 붙여넣기**: 기본 `Code.gs`의 내용을 지우고 이 저장소의 `backend/Code.gs` 내용을 붙여넣은 뒤 저장합니다.
4. **시간대 확인**: 시트의 파일 → 설정에서 시간대가 `(GMT+09:00) 서울`인지 확인합니다. 백엔드는 시트 시간대를 기준으로 동작합니다.
5. **`setup` 실행**: 편집기 위쪽의 함수 목록에서 `setup`을 고르고 실행합니다. 처음에는 권한 승인을 요청합니다. `records` 탭과 헤더가 생기고 전체 열이 일반 텍스트 형식이 됩니다. 여러 번 실행해도 안전합니다.
6. **비밀번호 설정**: 프로젝트 설정 → 스크립트 속성에 `EDIT_PASSWORD` 속성을 추가하고 값을 넣습니다. 값이 없으면 모든 쓰기가 거부됩니다. 코드에는 비밀번호를 넣지 않습니다. 서버에 시도 횟수 제한이 없으므로 12자 이상으로 길게 정합니다.
7. **웹 앱 배포**: 배포 → 새 배포 → 유형 "웹 앱"을 고릅니다. 다음 사용자 인증 정보로 실행은 **나**, 액세스 권한이 있는 사용자는 **모든 사용자**로 둡니다. 발급된 `/exec`로 끝나는 URL을 복사합니다.
8. **URL 넣기**: `config.js`의 `apiUrl`에 그 URL을 넣습니다.
9. **GitHub Pages 활성화**: 저장소 Settings → Pages에서 배포 대상 브랜치와 루트 폴더를 선택합니다.

### Apps Script를 고친 뒤에는

`Code.gs`를 고치고 저장만 해서는 웹 앱에 반영되지 않습니다. 배포 → 배포 관리 → 연필 아이콘 → 버전에서 **"새 버전"** 을 골라 재배포해야 합니다. 이렇게 하면 URL은 그대로입니다.

## 시트를 직접 고칠 때

- `records` 탭의 열은 `id, date, name, cups, updatedAt` 순서입니다.
- 형식이 맞지 않는 행은 달력과 합계에서 빠지고, 화면에 "형식이 맞지 않아 건너뛴 시트 행 n개" 경고가 나옵니다.
- 이름이 `=`, `+`, `-`, `@`로 시작하면 수식 삽입을 막기 위해 거부합니다.

## 로컬에서 실행과 테스트

Node 22 이상이 필요합니다. 설치할 의존성은 없습니다.

```sh
node --test test/      # 테스트
node test/server.mjs   # http://127.0.0.1:4173 (비밀번호 test-password, 데이터는 메모리에만)
```

로컬 서버는 실제 `backend/Code.gs`를 가짜 Apps Script 환경에서 실행합니다. 고장 재현용 주소가 있습니다.

```sh
curl -X POST 'http://127.0.0.1:4173/__fail?on=1'   # /api가 500을 돌려줌 (?on=0으로 복구)
curl -X POST 'http://127.0.0.1:4173/__bad-row'     # 형식이 틀린 행 추가
```
